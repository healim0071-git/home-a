### [ISSUE-01] Goldmark Markdown 파서의 코드블록 오인식 및 HTML 렌더링 깨짐

#### 1. 증상 및 현상
- Hugo Blox의 랜딩 페이지 마크다운(`content/*/_index.md`)은 YAML frontmatter 내의 `text: |` 블록 안에 HTML 코드를 포함하여 렌더링합니다.
- 특정 섹션의 인덴트(들여쓰기)가 불균일할 때, 브라우저 상에서 정상적인 UI 카드로 렌더링되지 않고 마크다운 인용 블록이나 회색의 `<pre><code>` 코드 블록 문자열로 노출되는 현상이 발생했습니다.

#### 2. 근본 원인 (Root Cause)
- Hugo의 기본 마크다운 파서인 **Goldmark**는 CommonMark 표준을 준수합니다.
- CommonMark 규칙에 따르면, 이전 기준선보다 **공백이 4칸 이상 추가로 들여쓰기된 줄은 '들여쓴 코드 블록(Indented Code Block)'**으로 자동 파싱됩니다.
- YAML frontmatter의 `text: |` 하위 항목이 8칸이 아닌 12칸 이상의 임의 들여쓰기를 가질 경우, Goldmark가 이를 HTML이 아닌 코드 블록으로 해석하여 렌더링을 중단했습니다.

#### 3. 조치 내용 및 해결책
- Node.js 스크립트를 작성하여 `text: |` 아래의 모든 HTML 태그 및 텍스트 라인의 선행 공백을 **정확히 8칸 스페이스(`        `)**로 정규화했습니다.
- 모든 섹션의 시작 태그부터 닫는 태그까지 8칸 인덴트 규칙을 강제하여 코드블록 오인식 현상을 원천 차단했습니다.

#### 4. 검증 결과
- Hugo 로컬 빌드 및 실시간 서버(`http://localhost:1313/`) 렌더링 결과, 모든 카드가 온전한 스타일이 적용된 HTML UI로 정상 출력됨을 확인했습니다.

### [ISSUE-02] 가독성 저하 및 초소형 폰트(11px) 불균형 문제

#### 1. 증상 및 현상
- 자율신경 치료 페이지의 06번 카드(동반질환 세부설명: 공황장애, 불면증, 불안장애, 어지럼증) 및 07번 카드(5단계 회복 로드맵) 등의 세부 문구가 `text-[11px]`로 선언되어 있었습니다.
- 고해상도 모니터(FHD/QHD) 및 모바일 기기에서 텍스트가 지나치게 작아 눈에 띄지 않고 흐릿하게 보이며, 브랜드가 추구하는 프리미엄 의료진 안내로서의 신뢰도가 떨어졌습니다.

#### 2. 근본 원인 (Root Cause)
- 복잡한 정보를 좁은 카드 안에 우겨넣으려는 과정에서 Tailwind 임의 픽셀 단위(`text-[11px]`)가 다수 남용되었습니다.
- 페이지 전반의 텍스트 타이포그래피 최소 크기(Minimum Font Size)에 대한 규격이 설정되지 않았습니다.

#### 3. 조치 내용 및 해결책
- 전체 파일 검색을 통해 `text-[11px]` 인스턴스 13건을 전수 발굴했습니다.
- **최소 글자 크기 하한선 정책 수립**:
  - 모바일: 최소 `12px` (`text-xs`) 이상
  - PC 데스크톱: 최소 `13px` (`text-[13px]`) 이상
- **위계 비례 조정**:
  - 서브 타이틀: `text-xs md:text-sm font-bold` (12px ~ 14px)
  - 서브 텍스트(A, B 포인트): `text-xs md:text-[13px]` (12px ~ 13px)
  - 검사 도구 배지, 악순환 차단 흐름 배지 등도 모두 동일한 하한선 기준으로 상향 통일했습니다.

#### 4. 검증 결과
- Chrome DevTools Protocol 기반 검증 스크립트 실행 결과:
  - 데스크톱(1280px): A포인트 13px, B포인트 13px, 타이틀 14px, 본문 최소 13px 확인
  - 모바일(390px): A포인트 12px, B포인트 12px, 타이틀 12px, 본문 최소 12px 확인
  - `text-[11px]` 잔존 건수: **0건 (완전 소멸)**

### [ISSUE-03] PC 환경에서 불필요한 단어 줄바꿈 발생 현상

#### 1. 증상 및 현상
- 커뮤니티 페이지(`/community/`)의 헤더 설명문:  
  *"전국 15개 네트워크 해아림한의원의 축적된 임상 노하우와 치료 정보, 환자 호전 사례, 원장단 의학 칼럼 및 영상을 투명하게 공유합니다."*  
  이 문장에서 PC 모니터의 넓은 가로폭이 있음에도 불구하고, 끝부분의 **"투명하게 공유합니다"**만 2번째 줄로 떨어지는 부자연스러운 줄바꿈이 발생했습니다.

#### 2. 근본 원인 (Root Cause)
- `<p>` 태그에 Tailwind의 `max-w-3xl` 클래스가 적용되어 있었습니다.
- `max-w-3xl`은 CSS로 `max-width: 48rem (768px)`에 해당합니다.
- PC 화면 폭이 1280px이나 1920px이어도 본문 폭이 강제로 768px로 묶여 있어, 약 64자의 한글 문장이 1줄에 들어가지 못하고 꺾였습니다.

#### 3. 조치 내용 및 해결책
- 중복되고 어색한 수식어 **'투명하게'를 삭제**하여 간결화:  
  *"...원장단 의학 칼럼 및 영상을 공유합니다."*
- 폭 제한을 해제하고 반응형 줄바꿈 속성을 부여:  
  `class="text-[#555555] text-base md:text-lg leading-relaxed max-w-none lg:whitespace-nowrap break-keep"`
- **PC 데스크톱(`lg:`, 1024px 이상)**: `lg:whitespace-nowrap`을 통해 강제로 1줄 유지.
- **모바일/태블릿(`lg:` 미만)**: `break-keep`을 통해 단어 단위로 3줄 자연스럽게 줄바꿈 처리.

#### 4. 검증 결과
- 데스크톱(1280px 및 1024px): `lineCount: 1`, `height: 29.25px`, `overflow: false` (완벽한 1줄 유지)
- 모바일(390px): `lineCount: 3`, 단어가 중간에서 끊기지 않고 문맥 단위로 정돈됨 확인.

### [ISSUE-04] 모바일 뷰포트(390px / 360px) 가로 스크롤 및 오버플로우

#### 1. 증상 및 현상
- 스마트폰 브라우저에서 화면을 좌우로 밀었을 때 흰색 여백이 나타나거나 가로 스크롤바가 생기는 현상(Horizontal Overflow).
- 자율신경 7대 치료 체계의 5단계 로드맵 박스, 8대 생활관리 수칙 그리드 등 다열 카드가 좁은 화면에서 화면 밖으로 삐져나오는 문제.

#### 2. 근본 원인 (Root Cause)
- 데스크톱용 4열/5열 그리드가 모바일 뷰포트(`min-width: 640px` 미만)에서 적응형 분기 처리가 부족했거나, 카드 내부 요소의 `padding`과 `gap`이 너무 커서 360px 뷰포트를 초과함.

#### 3. 조치 내용 및 해결책
- 모바일 우선(Mobile-First) 브레이크포인트 설계:
  - 8대 생활관리 수칙: `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-2.5`
  - 5단계 로드맵: `grid-cols-1 sm:grid-cols-5 gap-2`
  - 3대 핵심 원칙: `grid-cols-1 md:grid-cols-3 gap-4`
- 모바일 화면에서는 1열(세로 스택) 또는 2열로 자동 배치되어 가로폭 360px 내에 완벽히 수납되도록 수정.

#### 4. 검증 결과
- Headless Chrome을 통해 390px 및 360px 화면에서 평가한 결과:
  - `document.documentElement.scrollWidth === window.innerWidth`
  - `overflow: false` 100% 통과 (가로 스크롤 0px 달성).

### [ISSUE-05] 백그라운드 환경과 Windows 세션 격리로 인한 Git 브라우저 인증 미출력

#### 1. 증상 및 현상
- AI 코딩 어시스턴트의 터미널 도구를 통해 `git push -u origin main`을 실행했을 때, Git Credential Manager의 GitHub OAuth 브라우저 로그인 창이 사용자 모니터에 나타나지 않고 프로세스가 대기 상태에 멈추는 현상 발생.

#### 2. 근본 원인 (Root Cause)
- **Windows 세션 격리(Session Isolation) 보안 메커니즘**:
  - AI 어시스턴트의 명령어 실행기는 시스템 백그라운드 서비스(비대화형 세션, Non-interactive Session)에서 서브프로세스를 생성합니다.
  - Windows 운영체제는 백그라운드 서비스 프로세스가 사용자의 활성 대화형 데스크톱 세션(Session 23)에 GUI 창(Chrome 브라우저 또는 로그인 팝업 창)을 띄우는 것을 보안상 차단합니다.
  - 이로 인해 Git Credential Manager가 브라우저를 열려고 시도하지만 화면에 표시되지 못하고 응답 대기 상태로 블로킹되었습니다.

#### 3. 조치 내용 및 해결책
- **해결 방안 A (원클릭 배치 파일 제공 - 채택)**:
  - 사용자가 탐색기에서 직접 더블클릭할 수 있는 [`push_to_github.bat`](file:///d:/autonerve/push_to_github.bat) 스크립트 작성.
  - 사용자의 대화형 세션에서 실행되므로 즉시 브라우저가 열리고 1클릭으로 인증 완료 가능.
- **해결 방안 B (토큰 PAT 연동 지원)**:
  - Personal Access Token을 원격 URL에 주입하여 브라우저 인증 없이 백그라운드에서 완전 자동 푸시할 수 있는 환경 가이드 마련.

#### 4. 검증 결과
- 로컬 저장소의 `main` 브랜치에 Initial Commit(`8eca8c0`) 및 `chore` 커밋(`8b62f1f`)이 안전하게 보존되어 있으며, `origin` 주소가 `https://github.com/healim0071-git/home-a.git`으로 정확히 바인딩됨 확인.

## 3. 품질 보증(QA) 상시 점검 체크리스트
